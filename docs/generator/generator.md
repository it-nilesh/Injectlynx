# Generator

Injectlynx uses a Roslyn incremental source generator. The configuration path is a restricted C# convention DSL in module-level `Configure(IServiceConventionBuilder services)` methods. The generator reads fluent calls from syntax and semantic constants; it does not execute user code.

## Convention DSL

```csharp
public static class ApplicationServiceConventions
{
    public static void Configure(IServiceConventionBuilder services)
    {
        services
            .FromNamespace("Shop.Application.Services")
            .WhereNameEndsWith("Service")
            .AsMatchingInterface()
            .WithScopedLifetime();
    }
}
```

DSL arguments must be compile-time-readable. Namespaces and name filters must be non-empty constant strings, and open generic filters must use `typeof(IRequestHandler<>)`.

## Implemented Strategies

- `MatchingInterface`: `OrderService` registers as `IOrderService` when the class implements that interface.
- `ImplementedInterfaces`: a class registers against every implemented interface.
- `Self`: a class registers against itself.
- `MatchingInterfaceAndSelf`: combines matching-interface registration with self registration.
- `AssignableToOpenGeneric`: filters candidates assignable to an open generic interface.

## Generated Code

Generated files use:

- `// <auto-generated />`
- `#nullable enable`
- Fully qualified `global::` type names.
- Direct `ServiceCollectionServiceExtensions.AddScoped`, `AddSingleton`, or `AddTransient` calls.
- Stable ordering by contract and implementation.
- Registration reason comments before every generated registration.

## Development Investigation

To see registration mappings during development, enable the opt-in report:

```bash
dotnet build -p:InjectlynxDevelopmentReport=true
```

This emits `INJ900` info diagnostics such as `OrderService -> IOrderService`. For normal console-visible output, temporarily use:

```bash
dotnet build -p:InjectlynxDevelopmentReport=warning
```

Keep the report disabled in CI and production builds.

## Build-Time Performance

Injectlynx moves convention discovery into source generation. Runtime startup should be compared with manual Microsoft DI registrations, while generator cost should be measured as build-time overhead.

Use the large-consumer smoke script when validating source-generator behavior at scale:

```bash
SERVICE_COUNT=500 TARGET_FRAMEWORK=net10.0 bash eng/validation/measure-generator-performance.sh
```

See [Performance And Benchmarks](../benchmarks/performance.md) for the benchmark plan.

## Current Limitations

- DSL parsing is intentionally restricted and reports `INJ504` for non-deterministic declarations.
- Constructor validation covers public constructor availability, multiple public constructors, self dependencies, missing dependencies, simple cycles, and direct singleton-to-scoped dependencies.
- Open generic registration generation supports simple open generic definitions; full generic constraint validation remains future work.
